# not_a_music

Телеграм-бот для бесплатного поиска и прослушивания музыки. Источник — SoundCloud,
резерв — YouTube (если трек защищён SoundCloud Go+/DRM).

## Возможности

- Поиск по SoundCloud с постраничной выдачей; премиум-треки SoundCloud Go+ отсеиваются.
- Резервный поиск/скачивание с YouTube, если трек недоступен целиком.
- **Избранное** (⭐️ прямо в выдаче, без открытия трека) и **плейлисты** (➕ тоже из выдачи).
- **История прослушиваний** (🕘, хранится 30 дней) с удалением отдельных треков и очисткой.
- **Недавние запросы** (🔁) на экране поиска.
- **Топ плейлистов** (🏆) и **случайный трек** (🎲).
- **Шаринг трека** в другие чаты кнопкой ✈️ под треком (инлайн-режим).
- Профиль: язык ru/en, видимость, «О себе» и **статистика** (прослушано/лайки/избранное/плейлисты).
- Раздел «ℹ️ Помощь» с правилами и политикой конфиденциальности прямо в боте.
- Инлайн-режим: поиск музыки в любом чате (`@bot запрос`).

Всё управление — только кнопками, команд-меню у бота нет.

## Быстрый старт

```bash
cp .env.example .env        # или создайте .env вручную
# укажите BOT_TOKEN, полученный у @BotFather
pip install -r requirements.txt
python main.py
```

## Развёртывание на сервере

```bash
sudo bash deploy.sh
```

Скрипт ставит зависимости, создаёт venv, обновляет `.env`, перезаписывает
systemd-юнит `not_a_music` и перезапускает сервис.

Токен можно передать явно:

```bash
sudo BOT_TOKEN='123456:AA...' bash deploy.sh
```

Иначе он берётся из `.env` рядом с проектом. Скрипт сразу проверяет токен
через `getMe` и предупредит, если Telegram отвечает «Unauthorized».

### Если в логах `TelegramUnauthorizedError: Telegram server says - Unauthorized`

Токен бота недействителен (отозван или указан неверно).

1. Получите новый токен у [@BotFather](https://t.me/BotFather) (`/mybots` → API Token).
2. Обновите `.env` (или запустите `deploy.sh` с `BOT_TOKEN=...`).
3. Перезапустите сервис: `systemctl restart not_a_music`.

Полезные команды:

```bash
systemctl status not_a_music
journalctl -u not_a_music -f
```

## Качество звука и почему нужен node/deno

Бот всегда старается отдать лучшую доступную дорожку:

- **SoundCloud** — сортировка по битрейту (обычно `hls_aac_160k`, 160 кбит/с).
  Прямых mp3-файлов SoundCloud почти не отдаёт, поэтому HLS-фрагменты скачивает
  сам yt-dlp (обычный поток их не умеет).
- **YouTube** — берётся максимальный битрейт (`140` = 128 кбит/с), а не первый
  попавшийся `139` (48 кбит/с, отсюда был «шакальный» звук).

YouTube требует JS-рантайм для расшифровки подписи `n-sig`. Без него yt-dlp
деградирует до 48 кбит/с и обрывает загрузку. `deploy.sh` ставит `nodejs`,
поэтому достаточно одного запуска скрипта. Проверить:

```bash
journalctl -u not_a_music -f | grep "JS"
```

Если в логах есть `No supported JavaScript runtime` — поставьте Deno вручную:

```bash
curl -fsSL https://deno.land/install.sh | sh
ln -sf "$HOME/.deno/bin/deno" /usr/local/bin/deno
systemctl restart not_a_music
```

Дополнительные настройки (в `.env`, применяются без правок кода):

| Переменная | Смысл |
|---|---|
| `YTDLP_JS_RUNTIMES` | рантаймы для n-sig, по умолчанию `deno,node`; можно `deno:/usr/local/bin/deno` |
| `YTDLP_COOKIES` | путь к `cookies.txt` — если даже с node YouTube режет качество |
| `YTDLP_PLAYER_CLIENT` | клиенты через запятую, например `default,android_vr` |
| `YTDLP_PROXY` | прокси, если IP сервера блокируют |
| `YTDLP_DL_WORKERS` | параллельных потоков при скачивании (по умолчанию 3) |
| `YTDLP_DL_RETRIES` | повторов упавшего блока (по умолчанию 3) |

Если источник временно недоступен, бот пишет в лог конкретную причину
(`[music] ...`), а не молчит — смотрите `journalctl -u not_a_music -f`.

## Поиск в SoundCloud: две независимые стратегии

1. Прямой запрос к `api-v2.soundcloud.com` (быстрее, сразу отдаёт `policy`/медиа).
2. Резервный путь — `yt-dlp scsearch` со своим обслуживанием `client_id`.

Если api-v2 три раза подряд падает, он временно отключается на 2 минуты, чтобы не
тормозить каждый поиск. Премиум-треки Go+ (30-секундные сниппеты, DRM, блокировки)
отсеиваются по данным обоих путей.

## Тесты

```bash
python -m unittest discover -s tests -t . -v
```

Тесты не требуют интернета и дополнительных зависимостей: проверяются прогресс-бар,
сборка названия трека, фильтр премиум-треков, пагинация поиска, а также что в
исходниках нет «вопросиков» вместо русских букв и иконок (защита от битой кодировки).
